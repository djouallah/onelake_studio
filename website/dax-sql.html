dax-sql

A compiler for Apache Ossie semantic models. It takes a model and a query, and writes one SQL SELECT, in DuckDB SQL or in T-SQL for Fabric's SQL analytics endpoint and Warehouse. A measure can be defined in DAX, as in Power BI, or in SQL.

dax-sql on GitHub npm install dax-sql

The model

An Ossie model, in YAML: datasets, their fields, relationships, and metrics. A metric's expression is DAX or SQL. A Power BI model.bim (TMSL) works too.

datasets:
  - name: Sales
    source: dbo.sales
    # fields: ProductKey, Amount
    metrics:
      - name: Sales Amount
        expression:
          dialects:
            - dialect: DAX
              expression: SUM(Sales[Amount])
      - name: Red Share
        expression:
          dialects:
            - dialect: DAX
              expression: >-
                DIVIDE(CALCULATE([Sales Amount],
                  Product[Color] = "Red"), [Sales Amount])
  - name: Product
    source: dbo.product
    # fields: ProductKey, Category, Color
relationships:
  - from: Sales
    to: Product
    from_columns: [ProductKey]
    to_columns: [ProductKey]

The query

DAX, as Power BI writes it (EVALUATE SUMMARIZECOLUMNS(…)), or SQL over the model, where a measure is AGG("name").

SELECT Product.Category, AGG("Sales Amount"), AGG("Red Share")
FROM model
GROUP BY ALL

The SQL

One SELECT, and its columns with their types. DuckDB SQL by default, and T-SQL with dialect: 'tsql'. This is dax-sql 0.1.6's output for the model and query above. DuckDB filters the red sales in the same scan; T-SQL has no FILTER clause, so it reads them in a second step.

DuckDB

WITH f3 AS (SELECT j4."category" AS "g0", SUM(t2."amount") AS "a0", SUM(t2."amount") FILTER (WHERE (((j4."color" = ('Red' COLLATE NOCASE))))) AS "a1" FROM "dbo"."sales" AS t2 LEFT JOIN "dbo"."product" AS j4 ON j4."product_key" = t2."product_key" GROUP BY j4."category")
SELECT q10."Category" AS "Category", CAST(q10."Sales Amount" AS DOUBLE) AS "Sales Amount", CAST(q10."Red Share" AS DOUBLE) AS "Red Share" FROM (SELECT s9."Category", s9."Sales Amount", s9."Red Share" FROM (SELECT * FROM (SELECT k1."Category" AS "Category", f3.a0 AS "Sales Amount", (f3.a1 / NULLIF(f3.a0, 0)) AS "Red Share" FROM (SELECT f3.g0 AS "Category" FROM f3) AS k1 LEFT JOIN f3 ON f3.g0 IS NOT DISTINCT FROM k1."Category") AS z8 WHERE z8."Sales Amount" IS NOT NULL OR z8."Red Share" IS NOT NULL) AS s9) AS q10

T-SQL

WITH f3 AS (SELECT j4."category" AS "g0", SUM(t2."amount") AS "a0" FROM "dbo"."sales" AS t2 LEFT JOIN "dbo"."product" AS j4 ON j4."product_key" = t2."product_key" GROUP BY j4."category"),
f7 AS (SELECT j6."category" AS "g0", SUM(t5."amount") AS "a0" FROM "dbo"."sales" AS t5 LEFT JOIN "dbo"."product" AS j6 ON j6."product_key" = t5."product_key" WHERE ((j6."color" = ('Red' COLLATE Latin1_General_100_CI_AS_KS_WS_SC_UTF8))) GROUP BY j6."category")
SELECT q11."Category" AS "Category", CAST(q11."Sales Amount" AS FLOAT) AS "Sales Amount", CAST(q11."Red Share" AS FLOAT) AS "Red Share" FROM (SELECT s10."Category", s10."Sales Amount", s10."Red Share" FROM (SELECT * FROM (SELECT k1."Category" AS "Category", f3.a0 AS "Sales Amount", (CAST(f7.a0 AS FLOAT) / NULLIF(f3.a0, 0)) AS "Red Share" FROM (SELECT f3.g0 AS "Category" FROM f3 UNION SELECT f7.g0 AS "Category" FROM f7) AS k1 LEFT JOIN f3 ON f3.g0 IS NOT DISTINCT FROM k1."Category" LEFT JOIN f7 ON f7.g0 IS NOT DISTINCT FROM k1."Category") AS z9 WHERE z9."Sales Amount" IS NOT NULL OR z9."Red Share" IS NOT NULL) AS s10) AS q11

DAX's meaning, not only its syntax

The filter context, CALCULATE and its modifiers, relationships and the blank row work as they do in Power BI. The results are tested against Power BI's own answers.

And back to DAX

sqlToDax turns a SELECT over the model into the DAX query it stands for, so a Power BI semantic model can run it.

EVALUATE SUMMARIZECOLUMNS('Product'[Category],
  "Sales Amount", 'Sales'[Sales Amount],
  "Red Share", 'Sales'[Red Share])

In OneLake Studio

Semantic model queries, the Visual, Open in Excel and Export to Fabric all run on dax-sql. In the app and the extension it writes DuckDB SQL; an exported app on a semantic model sends DAX.
