Write to OneLake

SQL in OneLake Studio can write to a lakehouse. It makes and changes tables as Iceberg, adds rows to a Delta table, and writes files to Files/. The data goes straight from DuckDB on your machine to OneLake.

Off until you turn it on

Three settings, under Settings › OneLake Studio › Writes, say what SQL may write. Each is read when a statement runs, so a change applies at once, in the SQL box and on the command line. When the setting a statement needs is off, the statement is refused and nothing is sent to OneLake.

SettingDefaultWhat it allows
Allow Table WritesOffEvery write to a lakehouse's tables and schemas.
Allow Drop TableOffDROP TABLE on an Iceberg table. It also needs Allow Table Writes. It can't be undone.
Allow Copy to FilesOnCOPY to a lakehouse's Files/. It needs no other setting.

There is no dialog. Running a statement is the consent, once its setting is on.

What you can write

StatementWhat it writes
CREATE TABLE … (…), CREATE TABLE … AS …A new table, always as Iceberg.
INSERT INTO, UPDATE, DELETE, MERGE INTO, ALTER TABLEAn Iceberg table.
INSERT INTOA Delta table: its rows are added to the table's Delta log.
DROP TABLE [IF EXISTS]An Iceberg table: the table and its files are deleted.
CREATE SCHEMAA schema in a lakehouse with schemas.
COPY (…) TO '<ws>.<lh>/Files/<path>'A Parquet, CSV or JSON file in Files/. A file already at that path is replaced.

A table is named <workspace>.<lakehouse>.<schema>.<table>, as it is when you read it.

CREATE TABLE aemo.data.dbo.daily AS
SELECT settlementdate::DATE AS day, duid, sum(mw) AS mw
FROM aemo.data.dbo.scada
GROUP BY ALL
ORDER BY day;

INSERT INTO aemo.data.dbo.daily SELECT * FROM aemo.data.dbo.daily_staging;

COPY (SELECT * FROM aemo.data.dbo.daily) TO 'aemo.data/Files/export/daily.parquet' (FORMAT parquet);

New tables are laid out for Direct Lake

Every CREATE TABLE gets the Parquet layout that Direct Lake reads fastest, with nothing for you to write:

  • row groups of up to 4 million rows or 1 GiB;
  • files of up to 1 GiB;
  • pages of 1 MB.

These are Iceberg table properties, so every later write to the table uses them too. A property you set yourself in the statement's WITH (…) is kept. Sorting is up to you: add an ORDER BY to the query.

Delta tables

DuckDB's Delta writing is very limited, and OneLake Studio supports only what it can do on OneLake.

  • INSERT into an existing Delta table works.
  • UPDATE, DELETE, MERGE, ALTER TABLE and DROP TABLE on a Delta table are refused.
  • A Delta table that uses a feature DuckDB can't write is refused, and nothing is written. A table with column mapping, as Fabric writes it, is one of them.
  • A new table is never made as Delta. DuckDB can create a Delta table on your computer, but not yet on OneLake (duckdb-delta issue 432).

OneLake shows a Delta table as Iceberg too, but that Iceberg copy is read only: OneLake refuses any write to it.

What is refused

These are refused before anything is sent:

  • any DROP other than DROP TABLE, such as DROP SCHEMA or DROP VIEW;
  • CREATE OR REPLACE, INSERT OR REPLACE, ON CONFLICT, TRUNCATE and COPY … FROM;
  • a view, a macro, a secret or any other CREATE;
  • a write to a warehouse, a SQL database or a mirrored database;
  • a COPY to anywhere but a lakehouse's Files/;
  • any write while you are offline.

How a write runs

  • One statement runs at a time. Several statements separated by ; run in turn, and the first one that fails stops the rest.
  • Before it runs, DuckDB's own plan of the statement is checked: it must write what its text says, and only there.
  • An Iceberg write goes through the lakehouse's Iceberg catalog, attached for that one statement and detached after.
  • A write is never sent twice. If it fails, you see why, and it is not tried again.
  • After a write, the lakehouse's tables are listed again, so the tree and the next query see what was written.
