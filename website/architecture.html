Architecture

The app is the VS Code extension in a window of its own. One Node process signs in, names tables, keeps the catalog and answers Excel. DuckDB runs beside it in processes of its own. The window only draws.

Sync

Nothing waits on OneLake for an answer the catalog already holds. The catalog is one SQLite file per account, and the tree, SHOW ALL TABLES and Go To all read it.

  • What's open stays current. The sync worker, in the Node process, refreshes the workspaces open and pinned once their listings are older than catalogTtlMinutes.
  • The rest of the tenant, slowly. One process, holding a lease in the catalog file, reads every other listing each 12 hours: five every 15 seconds, one at a time, and a 429 stops it for a minute.
  • Tables in use are kept. A table read 3 times in 14 days has its metadata read every hour, and when nothing else is running each new snapshot is read whole, so it works offline, every column.
  • Offline asks nothing. With no connection or no session, no request is sent, and what was read keeps answering.

The servers

DuckDB runs outside the Node process, in a server that the first tab needing it starts. The Node process keeps the read-only guard and the names, and sends the server only statements it has checked.

  • Quack carries statements, through a pool of attaches. Stop finds a statement by a tag and cancels only that tab's.
  • The control pipe, an OS pipe, carries the OneLake token, the offline switch, and what Logs and Performance ask for, since Quack logs what it is sent.
  • The keep-offline engine is a second server, so reading a model's tables whole never holds the connection a query needs. The two share only the disk cache.
  • The server runs in UTC, as OneLake stores its timestamps in UTC, so a date table joins its facts.

Excel's XMLA endpoint

Excel's provider speaks XMLA over HTTP, so the Node process answers it itself. A model is one cube: a table is a dimension, a column an attribute hierarchy, a measure a member of [Measures].

Excel (MSOLAP) --XMLA over http://127.0.0.1--> Node process
  Discover -> the model's tables, columns and measures, as a cube
  Execute  -> MDX -> model SQL -> dax-sql -> the guard -> query server
  • Not an MDX engine. It reads the MDX a PivotTable writes, and refuses anything else by name, never by a guess.
  • Totals at their own grain. A subtotal is computed, not added up, so a distinct count or a ratio is right on every line.
  • Opened only when used. The port opens the first time Open in Excel is used, binds 127.0.0.1, and needs a token. A request from a browser is refused.

Export to Fabric

The one write, and it asks first: where it writes, before anything is written. It puts the model's file in its lakehouse's Files/, and publishes the app through the Fabric REST API.

  • The model isn't copied. The app's function reads it from the lakehouse at run time, so the app shows the model as it is there.
  • The tables are read in the browser. The function signs a read-only link for each table the model names, and refuses any other. DuckDB-WASM reads them in the page.
  • Protected. The page loads only for people who may open the app in Fabric.

Ports and tokens

Everything listens on 127.0.0.1 only, and nothing answers without its token.

WhoHowIts guard
WindowHTTP: events out, POSTs backThe first request's token becomes an HttpOnly, SameSite=Strict cookie. Another Host or Origin is refused.
Query serverQuack, on a local portA new random session token per server. Without it, the port runs nothing.
ExcelXMLA over HTTPA token in its address. Anything with an Origin is refused.
Command lineA local pipeNo port at all.

Sign-in is MSAL as the Azure CLI's public client, so there is nothing to register. Its token cache is encrypted for this Windows user, and the OneLake token reaches DuckDB as a storage secret.

In VS Code

The same parts, with VS Code as the shell and the window: it draws the tree and the tabs, and its Microsoft account provider signs in. On one machine, the app, the extension and the command line read one catalog and one cache.
